# Functional scope and acceptance

Authority: [master implementation request](katukina/sources/MASTER-IMPLEMENTATION-2026-10-26.txt), existing AGENTS.md and confirmed native-first decision. Original discovery is preserved in `docs/katukina/`. CONFIRMADO means requested/approved scope, not automatically working software. LEGADO OBSERVADO describes reported old behavior; PROPOSTO, A VALIDAR and BLOQUEADO are not accepted business policy.

| Module | Locally implemented behavior | Acceptance / remaining boundary |
|---|---|---|
| 01 Catalog | Native products/variations, master/packaging identity, SKU, native prices/media/tax classes, net/gross weight, origin, supplier, HS group, destinations, per-channel publication and variation purchasing | Listing, detail and cart must enforce publication; fixed prices extend the native editor. Existing product identity is frozen after first lot. |
| 02 Inventory | Integer physical/reserved/available ledger, receipt/adjustment, expiry, cancellation release, low-stock report, warehouses/location, supplier receipts, expected partial receipts, restock queue | Expected stock never counts as available. Concurrency/idempotency use SQL mutex. Live restock delivery requires authorized transport. |
| 03 Production | Planned/reserved/completed/cancelled jobs with multiple material/packaging inputs and outputs, explicit loss, exact conservation, cost allocation and traceability | Completion cannot double-post. Completed jobs cannot be edited/cancelled; supervised compensation is required. UI supports 10 rows per side; API up to 100. |
| 04 Relationships | Native customers and user credit; supplier/contact profiles without forced logins; product/lot associations, inbox links and customer order history | Purchasing history is limited to supplied receipt evidence; actual historical purchases require legacy source. |
| 05 Orders | Native HPOS order, separate operational stage, short note, picking, tracking, reservation, packing debit, cancellation release, inspected returns | 13 labels preserved; in_basket is cart-only. No automatic restock on returned/lost labels. Reship policy and accounting approval remain A VALIDAR; native replacement order can be linked by order notes. |
| 06 Channels | Active channel/domain/company/warehouse/countries, explicit publication, request context, per-channel fixed prices, native payment restrictions | One installation shares native tax/shipping administration and installation-wide capabilities. Independent legal-entity tax/tenant topology remains A VALIDAR; additional deployed frontends are not claimed. |
| 07 International | Early destination, native tax estimation and final address validation, explicit GBP/EUR price lists, customer currency preference, final total/address/items review | Base values are preserved. No automatic FX; settlement is unknown until provider evidence. Native price-range indexing is unavailable for alternate price lists. Taxes need verified real configuration. |
| 08 Customs | Verified jurisdiction/date rules including EU/GB/US, no default codes, exact-country precedence, ambiguity rejection, immutable order-line evidence, manifest and printable document | Commercial invoice/carrier-specific legal requirements remain A VALIDAR. Missing evidence prevents manifest generation. No invented classification. |
| 09 Shipping | Native country zones, configured PostNL/DHL/other manual service, currency-specific tariff, insurance limits/options and delivery-day estimates; native cart shipping quotation | Live carrier APIs/labels and historical shipping problems need source/contracts. Native notes and exact notice/version acceptance are retained. |
| 10 Payments | Native gateway settings, destination/channel rules, fictitious local gateway, bank-transfer native flow, full-balance authenticated store credit, signed adapter event contract, payment/refund deduplication and ledger | Live gateway protocol and credentials BLOCKED. Mixed tender/credit refund policy is A VALIDAR; do not model credit as an untaxed fee. |
| 11 Communications | Async normalized inbox, account filter, associations, templates, durable idempotent outbox, shipment/tracking/product instructions | Live mailbox/send adapters and authorized accounts BLOCKED. No email sent by this implementation session; tests use in-memory transports. |
| 12 Marketing/analytics | Native coupons/Analytics, consent and double opt-in, unsubscribe, explicit campaign queue/history, stock samples with physical debit, accounting CSV | Actual campaign delivery needs authorized provider. Privacy retention, bulk scale and historical accounting mapping require validation. |

Global acceptance requires persistence, permission denial, repeat-safe stock/money operations and actual tests, not only a menu/table. Refer to [implementation status](IMPLEMENTATION_STATUS.md) for executed evidence and [open decisions](OPEN_DECISIONS.md) for external dependencies. No staging verification, production readiness or deployment is implied.
